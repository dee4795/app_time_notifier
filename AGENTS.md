# AGENTS.md — Rules for the AI coding agent (Mindful Reminder app)

Read this file first. Then read `docs/PROJECT_BRIEF.md` (the full plan, decisions, and history).

## Who you are working with
- The developer is Deepak (Pune, India). He is a junior developer who builds with AI help.

## How to communicate
- Use **simple English**. Short sentences. No jargon without a one-line explanation.
- Work in **small steps**. After each step, say: what changed, why, and how to test it on the phone.
- Add short comments in the code that explain **why**, not only what.
- After each milestone, add a section to `docs/LEARNING_NOTES.md`: what we built, how it works in plain words, and 3 likely interview questions with short answers.
- If you are not sure about a fact (Android rules, Google Play policy, library versions), say "I am not sure, please verify" and point to the official documentation. Do not guess.
- Ask before big decisions. Do not change the plan silently.

## The project in 5 lines
- Android-only app. Name: "Mindful Reminder".
- The user picks a distracting app (for example Instagram) and a time limit.
- When the limit is reached, the app sends a **notification** with the user's own message and a photo of a loved one.
- The app does **not** block anything.
- Free: 1 monitored app. Paid upgrade: more apps and extras (see the brief).

## Hard rules (do not break these)
1. **No blocking of apps.** Do not use an Accessibility Service.
2. **Do not request `QUERY_ALL_PACKAGES`.** List launchable apps with a `<queries>` entry instead.
3. **No overlay permission** (`SYSTEM_ALERT_WINDOW`). Use notifications only.
4. **No backend for version 1.** All data stays on the phone. Photos never leave the phone.
5. **Do not add ads or tracking SDKs** without asking first.
6. **No medical claims** in default notification text. The user writes their own message.
7. **Do not edit generated files in `android/` by hand** if that folder is generated by Expo (see the brief, section 6). Put native code in a local Expo module or a config plugin so it survives `prebuild --clean`.
8. **Never commit secrets**: keystores, passwords, `.env` files, API keys.
9. **Ask before** changing the package name, adding any permission, adding a paid or third-party service, or changing the pricing logic.
10. Keep dependencies few. Prefer official Expo packages.
